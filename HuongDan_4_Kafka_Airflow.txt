--------------------------------------------------------------------
PHẦN 1: TRIỂN KHAI APACHE KAFKA (STREAMING INGEST)
--------------------------------------------------------------------
Mục tiêu: Xây dựng luồng dữ liệu thời gian thực mô phỏng hành động của người dùng (Streaming Data).

1. Tải và cài đặt Kafka 3.6.2 (Chạy ở chế độ KRaft, không cần Zookeeper)
   $ cd ~
   $ wget https://archive.apache.org/dist/kafka/3.6.2/kafka_2.12-3.6.2.tgz
   $ tar -xzf kafka_2.12-3.6.2.tgz
   $ cd kafka_2.12-3.6.2

2. Khởi tạo ổ đĩa và bật Kafka Server
   $ KAFKA_CLUSTER_ID="$(bin/kafka-storage.sh random-uuid)"
   $ bin/kafka-storage.sh format -t $KAFKA_CLUSTER_ID -c config/kraft/server.properties
   $ bin/kafka-server-start.sh -daemon config/kraft/server.properties

3. Tạo Topic (Kênh hứng dữ liệu) mang tên 'movie_logs'
   $ bin/kafka-topics.sh --create --topic movie_logs --bootstrap-server localhost:9092 --partitions 1 --replication-factor 1

4. Cài đặt thư viện Python kết nối Kafka
   $ pip3 install kafka-python-ng --break-system-packages

5. Viết và chạy file Producer (Bắn dữ liệu giả lập)
   - Tạo file `producer.py` tạo dữ liệu JSON (timestamp, user_id, movie_id, action, rating).
   - Chạy lệnh: $ python3 ~/producer.py

6. Viết và chạy file Spark Streaming (Hứng và xử lý dữ liệu)
   - Tạo file `spark_streaming.py` dùng Spark SQL đọc stream từ Kafka cổng 9092.
   - [LƯU Ý QUAN TRỌNG]: Trong `spark_streaming.py` cần có tùy chọn `.option("failOnDataLoss", "false")`
     để tránh lỗi crash stream khi khởi động lại Kafka hoặc lệch offset giữa các lần chạy.
   - Chạy lệnh: $ python3 ~/spark_streaming.py

7. [XỬ LÝ SỰ CỐ]: Khắc phục lỗi lệch Offset khi khởi động lại Kafka
   Nếu Spark Streaming báo lỗi: "Partition movie_logs-0's offset was changed from X to Y...":
   Chỉ cần xóa thư mục checkpoint cũ trên HDFS để Spark đồng bộ lại từ đầu:
   $ hdfs dfs -rm -r -skipTrash /lakehouse/checkpoints/streaming_logs/

PHẦN 2: TRIỂN KHAI APACHE AIRFLOW (ORCHESTRATION)
--------------------------------------------------------------------
Mục tiêu: Tự động hóa quá trình chạy Batch Job PySpark mỗi ngày.

1. Cài đặt Airflow 3.3.2 
   (Nâng cấp lên bản 3.3.2 vì Python 3.14 của Ubuntu 26.04 không còn hỗ trợ Airflow 2.9)
   $ pip3 install apache-airflow==3.3.2 --break-system-packages -i https://pypi.tuna.tsinghua.edu.cn/simple

2. Tạo file chạy lệnh (CLI) tùy chỉnh cho Airflow (Khắc phục lỗi pip không sinh file airflow)
   $ cat << 'EOF' > ~/my_airflow
#!/bin/bash
exec python3 -m airflow "$@"
EOF
   $ chmod +x ~/my_airflow

   (Mẹo: Bạn cũng có thể gọi trực tiếp lệnh: python3 -m airflow <lệnh>)

3. Khởi tạo Database SQLite cho Airflow
   $ export AIRFLOW_HOME=~/airflow
   $ ./my_airflow db migrate

4. Khởi động Airflow Standalone (All-in-one)
   $ cd ~
   $ ./my_airflow standalone
   (Hoặc: python3 -m airflow standalone)

5. Lấy mật khẩu Admin và đăng nhập
   - Mở cửa sổ terminal mới, gõ lệnh đọc file chứa mật khẩu:
     $ cat ~/airflow/simple_auth_manager_passwords.json.generated
   - Mẫu kết quả: {"admin": "rQkxSVcQXRPZq7sZ"}
   - Truy cập http://localhost:8080 đăng nhập bằng tài khoản `admin` và mật khẩu lấy được ở trên.

6. Viết kịch bản tự động (DAG)
   - Tạo thư mục dags: $ mkdir -p ~/airflow/dags
   - Tạo file `movie_pipeline_dag.py` bên trong thư mục dags.
   - Sử dụng `BashOperator` để thiết lập lệnh chạy file: `python3 /home/dell/process_movies.py`
     (hoặc mở rộng chuỗi chạy `clean_data.py` và `train_als_recommendation.py`).
   - Thiết lập `schedule=timedelta(days=1)` (Chạy mỗi ngày).

7. Kích hoạt DAG trên giao diện
   - Tìm tên DAG: `movie_data_pipeline` trên thanh tìm kiếm.
   - Bật công tắc (Unpause) sang màu xanh.
   - Bấm nút Play (Trigger DAG) để chạy.
   - Vào mục Logs của Task để kiểm tra kết quả (Bảng danh sách các bộ phim).
   - Lưu ý: Cần tắt dòng `time.sleep(600)` trong file Spark để DAG báo Success nhanh chóng.

1. FILE: producer.py (Lưu tại thư mục gốc ~/)
Vai trò: Bắn dữ liệu mô phỏng log hành động của người dùng (như click, view, rate) vào Kafka theo thời gian thực.
--- Source Code ---
import json
import time
import random
from datetime import datetime
from kafka import KafkaProducer

producer = KafkaProducer(
    bootstrap_servers=['localhost:9092'],
    value_serializer=lambda v: json.dumps(v).encode('utf-8')
)
actions = ['click', 'view', 'add_to_watchlist', 'rate']

print("🚀 Đang bắn dữ liệu giả lập vào Kafka (Bấm Ctrl+C để dừng)...")
while True:
    action = random.choice(actions)
    data = {
        'timestamp': datetime.now().strftime("%Y-%m-%d %H:%M:%S"),
        'user_id': random.randint(1, 1000),
        'movie_id': random.randint(1, 10000),
        'action': action
    }
    if action == 'rate':
        data['rating'] = round(random.uniform(1.0, 5.0), 1)
    
    producer.send('movie_logs', value=data)
    print(f"Đã gửi: {data}")
    time.sleep(1)

2. FILE: spark_streaming.py (Lưu tại thư mục gốc ~/)
Vai trò: Hứng dữ liệu từ Kafka (topic: movie_logs) và ghi xuống kho dữ liệu HDFS thành các file dạng CSV.
--- Source Code ---
from pyspark.sql import SparkSession
from pyspark.sql.types import StructType, StructField, StringType, IntegerType, DoubleType
from pyspark.sql.functions import col, from_json

# Khởi tạo Spark Session
spark = SparkSession.builder \
    .appName("MovieLogStreaming_Production") \
    .config("spark.jars.packages", "org.apache.spark:spark-sql-kafka-0-10_2.12:3.5.1") \
    .master("local[*]") \
    .getOrCreate()
spark.sparkContext.setLogLevel("ERROR")

# Định nghĩa Schema cho bản tin JSON từ Kafka
schema = StructType([
    StructField("timestamp", StringType(), True),
    StructField("user_id", IntegerType(), True),
    StructField("movie_id", IntegerType(), True),
    StructField("action", StringType(), True),
    StructField("rating", DoubleType(), True)
])

# Đọc luồng dữ liệu từ Kafka
# Cấu hình failOnDataLoss=false để tránh lỗi văng stream khi Kafka khởi động lại hoặc lệch offset
df_kafka = spark.readStream \
    .format("kafka") \
    .option("kafka.bootstrap.servers", "localhost:9092") \
    .option("subscribe", "movie_logs") \
    .option("startingOffsets", "latest") \
    .option("failOnDataLoss", "false") \
    .load()

# Bóc tách và chuyển đổi dữ liệu từ chuỗi JSON
df_parsed = df_kafka.selectExpr("CAST(value AS STRING)") \
    .select(from_json(col("value"), schema).alias("data")) \
    .select("data.*")

print("🚀 Hệ thống đang hứng dữ liệu từ Kafka và LƯU TRỮ XUỐNG HDFS...")

# Ghi dữ liệu luồng liên tục xuống HDFS
query = df_parsed.writeStream \
    .outputMode("append") \
    .format("csv") \
    .option("header", "true") \
    .option("path", "hdfs://localhost:9000/lakehouse/silver/streaming_logs/") \
    .option("checkpointLocation", "hdfs://localhost:9000/lakehouse/checkpoints/streaming_logs/") \
    .start()

query.awaitTermination()

Vai trò: Kịch bản cho Airflow tự động chạy file Batch (process_movies.py) định kỳ mỗi ngày.

from datetime import datetime, timedelta
from airflow import DAG
from airflow.operators.bash import BashOperator

default_args = {
    'owner': 'admin',
    'depends_on_past': False,
    'retries': 1,
    'retry_delay': timedelta(minutes=1),
}

with DAG(
    'movie_data_pipeline',
    default_args=default_args,
    description='Pipeline chạy Spark Batch bằng BashOperator',
    schedule=timedelta(days=1), # Cú pháp của Airflow 3
    start_date=datetime(2026, 9, 24),
    catchup=False,
    tags=['bigdata_project'],
) as dag:

    run_spark_job = BashOperator(
        task_id='run_spark_processing',
        bash_command='python3 /home/dell/process_movies.py'
    )

    run_spark_job
